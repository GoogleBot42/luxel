# Tools directory

One-page index of every script and harness in the repo. Each file carries
its full usage in a header comment — this page exists so you know what to
open. Everything runs inside `nix develop` from the repo root unless noted.

Most of these drive a device or the mirror over HTTP; the routes they call
are documented once in [docs/api.md](api.md), not here.

## Device operations

| tool | what it does |
|---|---|
| `tools/deploy.sh <ip> [--fw-only\|--assets-only]` | The one-shot deploy: builds firmware + web app, OTAs the image (waits for the reboot), streams the asset archive. Serial flashing does NOT update assets — use this after any serial recovery. Against a `hosted-ui` device (docs/boards.md) the asset half refuses with an explanation; use `--fw-only`. |
| `tools/ota-push.sh <ip>` | Just the firmware OTA + comes-back-on-the-new-slot verification (deploy.sh calls it). Refuses images built without WiFi creds. |
| `tools/decode-backtrace.sh` | Symbolicate ESP32 panic backtraces from a serial log against the current ELF. |
| `tools/release.sh [X.Y.Z] [--dry-run]` | Cut a release tag (validates tag == firmware/Cargo.toml on origin/master, then tags via the Gitea API). The GitHub mirror's release workflow builds + publishes the assets — see docs/releases.md for the whole pipeline. |
| `firmware/serial.log` | Live serial feed from the dev unit (fed from outside the container — there is no in-container serial). Watch for `PANIC` / `panic: rebooting in 3s` / `pattern rejected`; the HTTP-side view of a soak hides reboots (the device is back in ~5 s and retries succeed). |

## Hardware verification

| tool | what it does |
|---|---|
| `tools/hw-bench.mjs <ip> [report.md]` | **The soak**: pushes all ~320 gallery patterns to a real device one by one (**45 min–2 h**; each pattern costs a flash slot write, so the wall clock tracks the device more than the pattern count — the Athom took ~2 h for 303 patterns on 2026-08-31, and the "15 min" in older notes predates the gallery doubling), samples fps/heap/vmerr per pattern, then measures fps vs pixel count (60→2048), restores the device, and writes `docs/bench-report.md`. The definitive "does the firmware survive real patterns" gate — run it with a serial-log monitor for panics. It restores the pixel count, brightness and pattern it found (it used to hardcode a 300 px restore; fixed 2026-08-30). **The sweep runs at whatever count the device was already on** — the report header and its fps line say which, and rig shape is load-bearing, so read that line before concluding anything about a pattern that failed (Gitea #193 was chased at 300 px for a bug that only bites at 60). |
| `tools/wire-check.sh <device-ip>` | curl-level contract check of the device HTTP surface (single Content-Type per response, Content-Length == body bytes incl. the flash-streamed routes, asset 200/304 caching headers, all four OPTIONS preflight headers, 404 shape). Run after any `firmware/src/server.rs` change lands on a device (see `.claude/rules/firmware.md`'s one-`Reply`-type rule, Gitea #167). Plain bash+curl, no devshell needed. |
| `tools/improv-provision.mjs <port> <ssid> <pass>` | Puts a stock/restored WLED (0.13+) onto the LAN over Improv-serial — one UART packet, zero button holds; WLED persists cfg.json + wsec.json so takeover credential inheritance works afterwards. `stty -F <port> 115200 raw -echo` first, and stop any serial capture (single-reader rule). Prints the device URL from WLED's reply. |
| `tools/event-soak.mjs <ip>` | Focused soak of external event injection (`POST /api/events` → `readEvent`): live-codes a counter pattern, injects ~30k events (steady 1–32 batches, malformed frames, 32-batch overflow bursts), verifies delivery/rejection/heap/fps over HTTP only (`/api/vars` is raw 16.16). First run 2026-08-22 on the Athom: all green. |
| `tools/rx-stress.mjs <ip> [secs] [px]` | **The WiFi RX-pool gate**: floods the device with DDP frames (~245 pkt/s × 300 px ≈ 220 KB/s inbound UDP) while 6 HTTP workers hammer the API, watching heap/vmerr/`slot` at 1 Hz. Required before touching `static_rx_buf_num`/`dynamic_rx_buf_num`/`ampdu_rx_enable` — esp-radio's allocations don't null-check, so an undersized pool is a StoreProhibited panic, not an error. Run a serial capture alongside it. Sets the pixel count for the run and restores what it found. |
| `tools/soak.mjs` | The host-side twin: same pattern-churn against `luxel serve` (the native mirror) — liveness/fps/memory without hardware. |
| `[BOARD=…] [EXTRA_FEATURES=…] tools/stack-check.sh [budget]` | Builds the firmware with `-Z emit-stack-sizes` and fails if any function's stack frame exceeds the budget (default 12 KB), or if the leftover `.stack` drops below 24 KB. Sees EVERY linked function incl. deps — catches what clippy's lints can't. `stack-check.py` is its ELF parser. Works for any board (default `board-pixelblaze-v3`); chip/target/toolchain come from `firmware/board-target.sh`, the shared board map that `firmware/build-esp32.sh` also sources. `EXTRA_FEATURES=small-chip` checks the RAM-constrained profile, which shifts the statics/stack split and so needs its own run (same env knob as `build-esp32.sh`). |
| `tools/size-report.py` | Flash-size breakdown of the firmware ELF (see docs/size-report.md for the methodology + history). |
| `tools/qemu/qemu-espressif.nix` (`nix build .#qemu-espressif`) | Flake-output Nix derivation for Espressif's QEMU fork (esp32 machine, flash-file backed), carrying the patches that make esp-rs firmware run: CPENABLE reset, DPORT `INTR_STATUS`, TIMG level-int gating (`tools/qemu/patches/`). Stock images boot to the WiFi task — see docs/research/qemu-emulation-spike.md for the CLI and the divergence notes. |
| `tools/qemu/takeover-test.py --stock <stock.bin> --fs <fs.bin> [--slot app0\|app1]` | **The WLED→Luxel takeover test, hardware-free.** Composes a 4 MiB flash in the exact state a real Athom is in when WLED's OTA updater has just accepted a Luxel upload (stock dump + configured WLED littlefs at 0x310000 + `result/luxel-fw-ota.bin` in an app slot + an otadata entry selecting it), boots it under the patched QEMU, and asserts the takeover's serial narration **and** the resulting flash bytes (Luxel table at 0x8000, `LXCF` inherited-creds record, the copied image, untouched littlefs, otadata/boot-guard state). `--slot app1` (default) exercises the full 920 KiB self-copy; `--slot app0` the skip-the-copy path; `--inject-fault` drops boot 1's program ops at sector 0x10000 via the emulator's m25p80 fault-injection patch (`LUXEL_FLAKY_WRITE`) and asserts the takeover's bounded reboot-to-retry recovers (issue #35). ~12 s / ~2 s / ~13 s. Needs `nix build .#luxel-fw-athom-music` first and the two **gitignored** dumps `athom-wled-stock.bin` / `athom-wled-fs-configured.bin` from the main checkout — local/agent harness, not CI. |
| `tools/qemu/run-all.py` (`nix develop -c python3 tools/qemu/run-all.py`) | **The QEMU test harness — one command runs every emulator-backed test.** Builds the athom firmware (`.#luxel-fw-athom-music` → `./result`) and Espressif's QEMU (`.#qemu-espressif` → `./result-qemu`, a separate out-link so the two builds don't clobber each other's symlink), autodetects the two gitignored Athom dumps (or `--stock`/`--fs`/`LUXEL_ATHOM_STOCK`/`LUXEL_ATHOM_FS`), then runs takeover (app1/app0/fault) + heap-regions (selfheal/rollback) and prints a pass/fail summary. `-k <substr>` filters; `--no-build` reuses existing out-links. Tests needing the dumps are **skipped**, not failed, when the dumps are absent. ~36 s warm. Add new QEMU tests to its `suite` list. |
| `tools/qemu/heap-regions-test.py --stock <stock.bin> --fs <fs.bin> [--mode selfheal\|rollback]` | **Regression test for the pre-guard `esp-alloc: Exceeded the maximum of 3 heap memory regions` panic** (root cause + fix: UPDATES.md 2026-08-16). Composes the post-upload takeover flash like takeover-test.py. `--mode selfheal` (default) stands in for the flash-read flake by poking esp-alloc's HEAP slot array to `Some` over the gdbstub at the first `add_region` (no firmware bytes changed — harness stays isolated), then asserts the panic fires **before** the boot println/ota::init and self-heals. `--mode rollback` pre-seeds the LXBG failed-boot counter at its threshold and asserts `ota::preboot_guard` rolls back to WLED **before** the allocators run (no panic), proving a deterministic pre-guard panic can no longer loop forever. ~8 s / ~1 s. Same inputs as takeover-test.py. |
| `tools/qemu/gdbrsp.py` | Dependency-free GDB Remote Serial Protocol client (software breakpoints, memory read/write, continue/step) for driving QEMU's gdbstub from the Python harnesses — no `gdb` binary, no pygdbmi. Used by heap-regions-test.py to inject the flake. Note: QEMU's xtensa gdbstub does not auto-step past a software breakpoint on `c`, so re-inject-every-boot loops must clear the breakpoint or single-step; heap-regions-test.py sidesteps this by pre-seeding flash for the deterministic case. |
| `tools/qemu/make-efuse.py [-o efuse.bin]` | Generates the eFuse backing image that presents chip revision v3.0 to the guest, so *unmodified release* firmware clears esp-hal's min-revision gate under QEMU. Attach with `-drive ...,id=efuse -global driver=nvram.esp32.efuse,property=drive,value=efuse` (add `snapshot=on` in CI — the model writes back on a fuse burn). |
| `tools/image-check.sh <elf-or-bin>` | Two gates in one. (a) Asserts load-bearing features (WLED takeover, AP provisioning, boot guard) are actually linked into a built image via their serial-string markers — the //SIZETEST regression guard. Feature-gated markers (e.g. `hub75`) are asserted only when `EXPECT_FEATURES` lists the cargo feature, and `hosted-ui` additionally asserts markers that must be **absent** — a subtractive mode fails by keeping the code it exists to remove. (b) **OTA-slot margin**: for app images (magic 0xE9, not ELFs) it fails below 3 % of the 1 MiB slot free and warns below 6 % — so an image that would strand an un-recoverable board reddens CI, not a device (Gitea #160, docs/boards.md). Tunable via `MIN_MARGIN_PCT` / `WARN_MARGIN_PCT` / `OTA_MAX`. Runs automatically in build-esp32.sh (ELF, markers only) and the release workflow (all 8 board images, both gates). |

## Compatibility: library, corpus & oracle

| tool | what it does |
|---|---|
| `[GRIDS="default 16x16"] [STRIPS="60 300 512"] tools/check-library.sh [dir]` | **The library sweep** — builds `luxel-cli` and runs `luxel check` (compile + LXBC round-trip + 3-frame smoke) over every pattern in `library/` on **five rigs**: two grids (`check`'s default 10×10 and 16×16) and three **mapless strips** (60/300/512 px). Rig shape is load-bearing: rig-width and `pixelCount` arithmetic goes OOB on one shape and not another. The strips are not redundant — with a map installed the engine picks `render2D`, so a 2D pattern's own 1D `render` fallback is code the grid rigs never execute (Gitea #193: a fallback dividing its row index by the matrix *width* handed `render2D` a `y >= 1` on any non-square pixel count — clean on both grids, out of bounds on the 60 px strip the Athom runs, and only a 45-minute hardware soak caught it). `STRIPS=` (empty) drops the strip half; the defaults stay clear of the PB-compat 10,240-element array budget, which a few patterns legitimately exceed at 2048 px. Prints a per-rig pass count, the file + engine stage/error for each failure, exits non-zero if any failed. The standing acceptance gate for engine/compiler/bytecode changes — baseline **303/303 on every rig**. Runs a **`//#` directive lint** first (Gitea #179): a control directive parses only trailing on the `export function` line or on the line directly above it, so one written inside the handler body is silently ignored and the control degrades to an unbounded 0..1 slider with no default — the lint fails the sweep, naming file:line, before any pattern is compiled. Prose comments that merely mention `//#` are not flagged (a hit needs `min`/`max`/`step`/`default` + `=`). `corpus/` has its own richer harness below. |
| `tools/wasm-smoke.mjs` | `cargo build --release --target wasm32-unknown-unknown -p luxel-wasm && node tools/wasm-smoke.mjs` — drives the wasm C ABI straight from Node (no browser, no bindings) and asserts the same golden pixels the native suite locks, plus controls/vars round-trip, compile-error line/col, the 2D map + transform path, and the `lx_set_pin`/`lx_pin_read` pin-injection ABI (idle → driven LOW → held → released). The cross-host determinism check: native ↔ wasm bit-identical. Its goldens mirror `crates/luxel-core/tests/{engine,semantics}.rs` — update both together. |
| `tools/corpus/fetch.mjs` | Fetches the community pattern corpus (~293 `.epe`) from patterns.electromage.com into `corpus/` (gitignored, never redistributed). **Clean-room rule: never copy corpus code into Luxel — see the describer-firewall policy.** |
| `tools/corpus/report.mjs` | `cargo build --release -p luxel-cli && node tools/corpus/report.mjs` — runs `luxel check` (compile + LXBC round-trip + smoke frames) over the whole corpus; aggregates pass rate, error buckets, missing-builtin usage into `tools/corpus/last-report.json`. Baseline: 291/293. The missing-builtin set is derived at run time from the `BUILTINS` table in `crates/luxel-core/src/vm.rs` (the `BKind::Todo` entries) — as of 2026-08-29 it is empty, so that section prints "none"; never re-hardcode it. |
| `tools/verify/gen-pairs.mjs` | Builds `tools/verify/pairs.json` — the port↔original pairing manifest (library provenance line → `.epe` `name`, plus slug matching and a small fixup table) with a per-pattern rig hint. Names/paths only, no source: the fidelity judges read it. Coverage: 293/293 corpus patterns. |
| `tools/verify/snap.mjs` | **Judge-facing render harness.** `node tools/verify/snap.mjs <slug> [--seconds 6 --fps 20 --skip 0 --seed 1 --rig strip\|grid\|cloud --pixels N --grid WxH --controls-orig/-port "name=v" --vars-orig/-port "name=v" --pins-orig/-port "26=0|1|x" --undriven --label X --sheet-frames 12 --strip-frames 12 --strip-at S --sensors auto\|synth\|off --wall-clock N --probe-controls --probe-seconds 4 --dump "t1,t2"]` — renders the corpus original and its clean-room port headlessly under identical rig/seed/wall-clock/delta, into `tools/verify/out/<slug>/<label>/`: `{orig,port}.png` (grid rigs also `*-motion.png` filmstrip and `*-rhythm.png` column-mean waterfall; sheet/filmstrip cells are stamped with their absolute timestamp in a built-in 3x5 font), `meta.json` (settings, run-level `warnings` for clamped args, per-side controls (each `{name, kind, label}` plus `bounds` — the control's parsed `//#` directive — when it declares one, so a snap alone shows whether a directive bound), per-side `varsExported`/`varsApplied` (the exported-var surface and what was pushed into it), per-side `pinsApplied` (the digital input pins driven into it), compile/runtime errors, per-side `wantsSensors`/`sensors`(/`sensorModel`), `statsSummary` (avg/min/max/first/last, `zeroMotionFrames`, `brightnessTrend`), and a `provenance` stamp of git sha + port/epe/harness sha256 so a stale cached run can be spotted — short enough to read whole), `stats.json` (the full per-frame brightness/RGB/motion series, one line each), and with `--probe-controls` a `probe.json` sweeping every settable dial one at a time across its OWN `//#` min/mid/max (raw 0/0.5/1 only for a dial with no usable bounds — which is every corpus original, since PB has no directives; the step-snapped midpoint keeps an integer dial on integers) and reporting per-dial `{bounds, probedAt, boundsProbed, deltas, deltasLit, responsive}` + a stdout table that stars the bounds-driven sweeps, and with `--dump "t1,t2"` a `frames.json` of the exact per-pixel `[r,g,b]` values at the captured frames nearest those times (grid rigs nested as rows) — the layout/colour numbers the upscaled PNGs alias away. Strip & cloud rigs render a waterfall; grid renders a contact sheet. `--pixels` is snapped where the rig demands a shape — the cloud rig is an n×n×n lattice so `--pixels` picks the side (`round(cbrt(N))`, default 5³=125) and the count becomes side³; the grid rig fills whole rows — and any snap is warned on stderr + in `meta.json`'s `warnings`. `--sensors` feeds a deterministic synthetic PB sensor-board frame (model `beat120`: 2 Hz/120 BPM beat envelope driving `energyAverage` + a 32-bin spectrum with a bass thump, a mid melody peak stepping an 8-step scale one step per beat, and an HF shimmer; `maxFrequency`/`maxFrequencyMagnitude` track the melody; an 8 s accelerometer tilt circle; constant `light` 0.5) before every warmup and captured frame — computed from frame index + fps only, so both sides get byte-identical input and reruns are bit-identical. `auto` (default) feeds a side only when its engine reports `lx_wants_sensors`, so non-sensor patterns render exactly as before; `synth` always feeds; `off` never does (the old idle-state view). Without it the ~50 corpus patterns binding `frequencyData`/`accelerometer` render black or frozen on both sides and are unjudgeable. **No output file ever contains pattern source** — the AI fidelity judges decide from pixels alone; the judge prompt is `tools/verify/JUDGE.md`; the batch-orchestration loop that feeds judges is `tools/verify/ORCHESTRATION.md`, and the sweep-wide defect synthesis is `tools/verify/FINDINGS.md`. Compile/runtime failures are recorded, not fatal; exit ≠ 0 only for harness errors. `--vars-orig`/`--vars-port` push values into a side's EXPORTED vars once after init, the way a companion app drives a pattern over PB's vars API — the two sides may name the same variable differently, so the flags are per side; an unknown name lands in that side's `warnings` instead of no-oping silently. `--pins-orig`/`--pins-port` DRIVE digital input pins into a side (`26=0` LOW, `26=1` HIGH, `26=x` release to the pin's `pinMode` idle level) — the stand-in for the GPIO the engine has no hardware for, so a button pattern can be pressed deterministically instead of idling at "never pressed" forever (Gitea #177); levels are applied once after init and HELD for the whole run, and a pin outside the engine's 0..63 window lands in that side's `warnings`. `--undriven` (old name `--no-vars`) drops the manifest's var, control AND pin pins for a run (an empty `--vars-*` does not), which is the only way to see a pinned pair in its genuinely UNDRIVEN state. Without it a client-DRIVEN original (one that lights only what an external client writes into its exported vars — `automap` was the canonical case before its 2026-08-31 deletion) renders black and reads as unrenderable. Supporting modules: `enginehost.mjs` (Node host for the engine wasm, headless twin of `web/src/lib/luxel.ts`), `png.mjs` (zero-dep PNG encoder + 3x5 bitmap font) and `hints.mjs` (the `//#` control-bounds parser + `directiveRange`, shared with the review UI, plain-JS twin of `web/src/lib/hints.ts`). |
| `tools/verify/report.mjs` | **Visual sweep report (static).** `node tools/verify/report.mjs [--slugs a,b --seconds 6 --fps 20 --gif-fps 10 --html-only --force]` — renders every judged pair as side-by-side animated GIFs (original vs port, same rig/seed/wall-clock/sensor conventions as snap.mjs; zero-dep GIF89a encoder with exact per-frame palettes) and writes `tools/verify/out/report/index.html`: cards grouped by verdict, click-to-expand judge details (summary/observations/dials/feedback), slug filter. Output is gitignored and regenerable; ~few minutes for all 293. The beat120 sensor synth is shared with snap.mjs via `tools/verify/sensormodel.mjs`. **Superseded by `review.mjs` for triage** — use it when you want a shareable/offline artifact (a static file tree, no server, GIFs that survive being copied around); use review.mjs when you want to drive the patterns and record decisions. |
| `tools/verify/review.mjs` | **Interactive review UI (the triage tool).** `cargo build --release --target wasm32-unknown-unknown -p luxel-wasm && node tools/verify/review.mjs [--port 4183]` — a zero-dep local web app that runs BOTH sides of all 293 pairs **live** in the browser on the engine wasm, under the sweep's exact conventions (same rig, seed 1, pinned wall clock, beat120 sensors where a side binds them, fixups.json `vars`/`controls`/`pins` pins pushed in after init — so a button pattern shows its PRESSED state rather than idling). List view: one card per pair with two live canvases (strip bar / pixelated grid / cloud z-slices), rig + verdict + decision badges, sweep summary, compact decision bar; sticky top bar with a global fps slider, pause/reset-all, verdict + decision-status filters and slug/name search. Click a card for a detail modal: bigger canvases, per-side control panels (sliders honouring `//#` bounds hints in both placements, hsv/rgb channel sliders, toggles, triggers, polled showNumber/gauge readouts), per-side reset, and the judge's full verdict (summary/observations/dials table/feedback). Performance: IntersectionObserver keeps only visible cards live, capped at ~40 engines, with one rAF loop round-robining a fixed step budget. **Decisions** (`delete` / `good` / `fork` + optional name / `needs-work`, each with an optional feedback note that goes verbatim to the fixing agent) persist immediately to the tracked `tools/verify/decisions.json` via an atomic tmp+rename write, so a review survives restarts and spans sittings. Everything is assembled at request time — edit a `library/*.js` or a verdict JSON and reload. Needs `corpus/` present (symlink it in a worktree); a missing `.epe` degrades to an "unavailable" original, not a crash. |
| `tools/verify/fixups.json` + `fixups.mjs` | Per-slug fixup manifest shared by snap.mjs, report.mjs and review.mjs. Six kinds: `stripLinesMatching` drops author-planted tripwire lines from the **original** at load time (the deliberately-invalid sentinels a pattern's README tells the user to delete — both `music-sequencer-*` originals are unjudgeable without this), and `rig`/`pixels`/`grid` override the rig for **both** sides where an original only renders on a specific geometry (`nano-orbital` ≥144 px, `nyan-lights` 300-px strip, `orv-christmas-tree` grid 20×20 — see SWEEP-NOTES.md), and `vars` pins per-side exported-var values pushed into each side after init for originals that only draw when a client drives them (no live entries since the 2026-08-31 review deletions — `automap` was the canonical case, `pixel` pinned mid-strip on both sides; pins stay per side because a pair may name the same var differently), and `controls` invokes per-side UI control values after init while `pins` DRIVES per-side digital input pins through the `lx_set_pin` injection ABI (Gitea #177) — both exist for a pair whose two sides expose the SAME input through different surfaces, the canonical case being `example-button-w-debounce`, where the original polls a real switch with `digitalRead(4)` under `INPUT_PULLUP` and the clean-room port offers a UI toggle because the engine has no GPIO: undriven, both sides sit at mode 0 forever and the debouncer is never exercised, while pinning `pins.orig.4 = 0` alongside `controls.port.toggleButton = 1` presses both buttons at t=0 and the two sides render byte-identically — and `nonVisual` is a reason string EXCLUDING a pair from the scored population because the original is not a visual pattern at all (`performance-test-framework`, a CPU benchmark read through Vars Watch whose correct render is black on real PB too — Gitea #123): snap.mjs warns loudly on every run of such a slug, report.mjs and review.mjs file it under a `non-visual` heading/badge with no score, and it must never be handed to a judge. Every entry carries a `note` citing why. An explicit `--rig/--pixels/--grid` on snap.mjs still wins, as does a `--vars-*`/`--controls-*` entry for the same NAME or a `--pins-*` entry for the same PIN; fixups in force are recorded in `meta.json`'s `provenance.fixups`, and the manifest is folded into `harnessSha256` so editing it invalidates cached runs. Not a place to patch patterns into working. |
| `tools/oracle/*` | The **differential oracle** against Jeremy's real Pixel Blaze (192.168.0.140, black-box via its public websocket; live-code only, nothing saved to it). `run.mjs` drives the `vectors.mjs` battery (exact 16.16 raws both sides); `pixels.mjs` diffs rendered RGB via previewFrame; `sweep.mjs`/`compare-sweeps.mjs` sample builtins over input grids into `sweeps/` for algorithm fitting; `mapdump.mjs` dumps/restores the device's installed pixel map losslessly (reconstructed from inside the pattern language); `probe.mjs` is a quick connectivity check; `oob-probes.mjs` is the self-judging out-of-range battery — blast radius (Gitea #84) plus the Q1–Q8 tolerance sweep that settled #107 (out-of-range reads/writes error on PB too; the splat builtins validate the whole span). Its header names two `arrayReplace*` shapes that reproducibly HANG the oracle — they are deliberately not in the battery, don't add them back. `todo-probes.mjs` is the self-judging battery that settled the last TODO(oracle) markers 2026-08-22 (palette edges, transform cap, rotate conventions, null/undefined, arity recon via the local PB compiler); `pb.mjs`/`compiler.mjs` are the client + PB's own compiler extracted for encoding parity. |

## CLI (`cargo run -p luxel-cli --` or `target/release/luxel`)

`run` (PPM frame strip) · `bench` (VM throughput) · `parse` (AST dump) ·
`check` (compile + bytecode round-trip + smoke, JSON line — the corpus
report's engine) · `compile` (source → `.lxbc`) · `pixels`/`vars` (oracle
halves) · `serve` (the native device-API mirror the web e2e runs against —
route reference in [docs/api.md](api.md)).

`serve --heap-free BYTES` makes the mirror report that much free heap from
`/api/status` instead of the default 0 ("this host has no meaningful number")
— how the editor's capacity warning (docs/webui.md) is exercised against a
starved device without hardware.
